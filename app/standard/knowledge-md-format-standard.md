# 知识库 Markdown 文档格式规范

## 适用范围

本规范适用于知识库中的 `.md` / `.markdown` 文档。

这些 Markdown 文档需要能够通过 `app/tools/json_to_md/json_to_md.py` 与 JSON 源数据相互转换，因此正文格式必须保持稳定、简单、可解析。

## 基本原则

- 文档内容必须使用简体中文，代码标识符、命令、文件路径、协议字段名除外。
- 一个文档只表达一个明确主题，避免把多个无关主题写入同一文件。
- 文件名必须使用英文小写、数字和连字符，例如 `user-login-guide.md`。
- 转换结果文件名必须与输入文件名一致，只替换目标格式后缀。
- 正文只使用本规范列出的 Markdown 块类型，避免使用当前转换工具无法稳定还原的语法。
- 标题、段落、列表、代码块、引用之间必须使用一个空行分隔。

## 推荐文档结构

知识库 Markdown 文档建议使用以下结构：

````md
# 文档标题

一段话说明本文档的用途、适用对象或结论。

## 背景

说明问题来源、业务背景或上下文。

## 规则

- 规则一
- 规则二
  1. 子规则一
  2. 子规则二

## 示例

```text
示例内容
```

## 注意事项

> 这里写关键约束、风险或例外情况。
````

## 支持的 Markdown 块

### 标题

标题只允许使用 `#` 到 `######`。

```md
# 一级标题

## 二级标题

### 三级标题
```

要求：

- 一级标题用于文档主标题，每个文档建议只出现一次。
- 标题文本必须与 `#` 之间保留一个空格。
- 不允许使用 Setext 标题，例如 `标题` 加 `===` 的写法。

### 段落

普通正文使用段落。

```md
这是一个段落。

这是另一个段落。
```

要求：

- 段落之间必须使用一个空行分隔。
- 段落中可以包含普通文本，但不要依赖复杂内联 Markdown 语法表达结构。

### 代码块

代码、命令、配置示例必须使用围栏代码块。

````md
```bash
python3 app/tools/json_to_md/json_to_md.py input.md -o dist
```
````

要求：

- 代码块必须使用三个反引号。
- 起始围栏建议声明语言，例如 `bash`、`json`、`text`。
- 结束围栏必须单独占一行。

### 无序列表

无序列表使用 `-`。

```md
- 第一项
- 第二项
```

要求：

- 同一个列表中不要混用 `-` 和 `*`。
- 列表项内容应保持为单行文本。
- 如需表达子项，可以使用嵌套列表。

### 有序列表

有序列表使用数字加英文句点。

```md
1. 第一步
2. 第二步
```

要求：

- 当前转换工具会识别有序列表，并在 JSON 中标记为 `ordered: true`。
- 列表项内容应保持为单行文本。
- 有序列表可以作为无序列表的子列表，也可以包含无序子列表。

### 嵌套列表与多级混合列表

嵌套列表通过缩进表达层级。每一级缩进使用两个空格。

```md
- 准备环境
  1. 安装依赖
  2. 运行测试
- 完成转换
```

要求：

- 每一级列表项内容必须保持为单行文本。
- 子列表必须挂在上一个列表项下面。
- 同一层级建议保持同一种列表类型，不同层级可以混用有序列表和无序列表。
- 不要在列表项内部嵌套代码块、引用、表格或段落。

### 表格

表格用于表达简单二维数据。

```md
| 字段 | 说明 |
| --- | --- |
| type | 块类型 |
| text | 文本内容 |
```

要求：

- 表格必须包含表头行和分隔行。
- 分隔行必须使用至少三个连字符，例如 `---`。
- 每一行的列数应与表头保持一致。
- 单元格内容应保持为普通文本，不要嵌入列表、代码块或引用。
- 当前工具不保留表格对齐信息。

### 链接引用定义

链接引用定义用于集中声明可复用链接。

```md
[转换工具]: app/tools/json_to_md/README.md "工具说明"
```

要求：

- 格式必须为 `[label]: url`。
- 标题可选；如果填写，必须使用英文双引号包裹。
- 每个 `label` 在同一文档内应保持唯一。
- 链接引用定义应作为独立块书写，前后使用空行分隔。

### 引用

引用用于表达关键提示、约束或注意事项。

```md
> 这是一个重要提示。
```

要求：

- 引用块每一行都必须以 `> ` 开头。
- 引用内容应简短，避免放入复杂结构。

### Markdown Frontmatter

Frontmatter 只允许出现在文档开头，用于保存文档元数据。

```md
---
title: 产品说明
tags:
  - 工具
---
```

要求：

- Frontmatter 必须使用 `---` 作为开始和结束分隔符。
- Frontmatter 必须位于文档第一行。
- 当前工具会将 Frontmatter 内容作为原始文本保存，不解析其中字段语义。

### 任务列表

任务列表用于表达检查项。

```md
- [x] 已完成事项
- [ ] 未完成事项
```

要求：

- 已完成项使用 `- [x]`。
- 未完成项使用 `- [ ]`。
- 任务内容必须保持为单行文本。
- 当前工具不支持嵌套任务列表。

### 脚注

脚注用于补充说明正文中的引用。

```md
正文中引用脚注[^note1]。

[^note1]: 这是脚注内容。
```

要求：

- 脚注定义格式必须为 `[^label]: 内容`。
- `label` 在同一文档内应保持唯一。
- 多行脚注的续行必须使用至少四个空格缩进。

### HTML 片段

HTML 片段用于保留 Markdown 无法表达的特殊内容。

```html
<div class="note">
  <p>提示</p>
</div>
```

要求：

- HTML 片段必须作为独立块书写，前后使用空行分隔。
- 当前工具会将连续的非空 HTML 行作为一个 HTML 块保存。
- HTML 内容不做结构校验，编写时必须保证标签自身有效。

## 块标记规范

如果文档需要和 JSON 源数据保持稳定同步，建议使用块标记。

```md
<!-- block:intro -->
这是产品的基础介绍。
<!-- /block:intro -->
```

要求：

- 每个块标记可以包裹一个或多个完整 Markdown 块。
- 开始标记格式必须是 `<!-- block:{id} -->`。
- 结束标记格式必须是 `<!-- /block:{id} -->`。
- `{id}` 必须与 JSON 源数据中的 `id` 完全一致。
- 同一文档内 `id` 必须唯一。
- 当块标记内包含多个 Markdown 块时，JSON 中会表示为 `group` 块。

推荐 `id` 命名：

```text
intro
background
rules
example-command
notice
```

## 不支持的写法

为了保证 Markdown 和 JSON 能稳定互转，知识库文档中不要使用以下语法：

- 图片

如果确实需要这些能力，应先扩展转换工具和 JSON 源数据规范，再允许文档中使用。

## 文件输出规则

使用转换工具时，输出文件名必须保持输入文件名不变，只替换后缀。

示例：

```bash
python3 app/tools/json_to_md/json_to_md.py knowledge/user-login.md -o dist
```

输出文件：

```text
dist/user-login.json
```

即使传入文件路径：

```bash
python3 app/tools/json_to_md/json_to_md.py knowledge/user-login.md -o dist/custom-name.json
```

输出文件仍然是：

```text
dist/user-login.json
```

## 转换前检查清单

- 文档是否只包含一个主题。
- 文件名是否使用英文小写和连字符。
- 标题、段落、列表、代码块、引用之间是否有空行。
- 是否只使用当前工具支持的 Markdown 块。
- 如使用块标记，`id` 是否唯一且与 JSON 源数据一致。
- 是否没有使用图片等未支持语法。
